# Changelog

## 5.0.0

Breaking: the archive format follows elykseer-ml 0.10.1 (`doc/08_Format.md`); archives of 4.x cannot be read.

- AES-256-GCM over each assembly: nonce = first 96 bits of the ivec, the aid as additional
  authenticated data, the tag in the last 16 bytes; decryption fails on a wrong key or aid,
  and on modified data. The last 16 rows of an assembly are reserved for the tag.
- identifiers: aid = SHA3-256(my_id ^ 256 random bits), chunk id = SHA3-256(my_id ^ cid ^ aid),
  file hash = SHA3-256(fname ^ my_id)
- layout: logical index i is at chunk (i mod n), offset (i div n); random header of
  min(n - 16, 128) bytes; block size 32768; a block that does not fit goes as a whole into
  the next assembly
- restore verifies the checksum of each block; recall fails unless all chunks are complete;
  the read cache no longer returns data of a different assembly and evicts an environment
  only after a successful restore
- an assembly's key is only kept if all its chunks were written
- meta data as XML following `schema/keys.xsd` and `schema/fileinformation.xsd`; key records
  carry the format version, keys of other formats are refused; the file information and the
  file blocks are written to one document `LXRbackup-*-files.xml` (replaces `-dbfb.xml` and
  `-dbfi.xml`); newer file information replaces older entries
- `LXRrestore` keeps the output below `-o` (refuses `..` and symlink escapes), removes
  partially restored files and exits with 1 if a file fails; `LXRbackup` exits with 1 if an
  assembly or the meta data cannot be written; `LXRverify` fails on missing results
- conformance tests with vectors generated by elykseer-ml (`tests/conformance/`); in CI, the
  vectors are regenerated in the elykseer-ml docker image, and an archive written by
  elykseer-ml is verified and restored by `LXRverify`/`LXRrestore`
